# Focused specialist assessment

Use independent expertise when the problem warrants its cost and delegation is available and authorized. This is the rich path, not a prerequisite for Markdown-only use. Do not spawn agents for routine edits or treat agreement as proof.

The package supplies `domain-assessor` and `alignment-tracer` agent definitions where a host can load them. In other rich environments, delegate their bounded prompts explicitly using the available agent tools. Give the actual source paths, target scope/revision, applicable acceptance and delivery scope, and the relevant shared references. Agent definitions are guidance, not a promise that every host registers native agents.

## Domain assessor brief

> Assess this plan's coherence and usefulness for the stated purpose. Explain the important concepts and responsibility boundaries from the supplied sources. Challenge realistic scenarios, independent changes, consumer questions, and compression assumptions. Distinguish missing decisions from contradictions. Do not demand one class/table per concept or treat derived concepts/discriminators as inherently wrong. Return evidence-backed concerns, alternatives, preserved strengths, and unexamined areas. Do not edit artifacts, ratify proposals, or implement changes.

## Alignment tracer brief

> Trace this bounded change through the supplied accepted plan sections, contracts, decisions, examples, code, comments, and tests at the named revision. Separate current obligations from future scope. Examine purpose and responsibility boundaries as well as behavior. Return clear mismatches, reasoned concerns, ambiguities, and coverage, with source/evidence pairs and proportionate follow-up. Missing accepted intent or missing repository review context is a dependency, not permission to infer requirements from code. Do not edit or publish.

The coordinating assistant owns the original job and reconciles findings against evidence. Preserve substantive disagreement; do not vote, merge speculative claims into certainty, or let agents concurrently rewrite normative files. Record useful project findings in reviewable artifacts and individual progress in the checkpoint.

Before a repository-only review, the optional [review-input checker](../../spec-audit/references/review-inputs.md) can establish whether selected documents are present in the committed snapshot. It cannot find every needed document, establish authority, or evaluate semantics. A Markdown-only reviewer performs the same reasoning using available repository files and states access limits. No automatic background hook or service mutation is required.
