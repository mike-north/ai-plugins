# Spec Skills

Two model-invoked skills for software specifications: `spec-audit` and
`spec-authoring`.

## Overview

- **spec-audit** — Use when auditing an implementation, test suite, generated
  artifact, pull request, migration, or behavior description against a governing
  specification. It judges whether behavior matches the spec, whether coverage
  proves it, whether a change broke an invariant or non-goal, and whether
  ambiguity in the governing documents is blocking a confident judgment.
- **spec-authoring** — Use when drafting, revising, or clarifying thorough
  software specs: design docs, architecture specs, requirements, protocol or
  schema specifications, and ADR-style technical decisions. It makes scope,
  invariants, expected outputs, validation criteria, non-goals, and edge cases
  explicit and testable.

Both skills are general-purpose and adapt to any project.
