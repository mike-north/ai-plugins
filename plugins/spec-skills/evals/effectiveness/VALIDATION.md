# Harness validation and calibration integrity

The harness tests are **infrastructure checks, not skill-effectiveness trials**. The test suite was written before the runner existed: its initial run failed importing the absent `harness.py`. Subsequent regression tests also failed before each corresponding repair. The retained development logs are under the experiment scratch area; no success count includes these synthetic tests as agent trials.

The standard-library suite currently covers path traversal and symlink rejection, reserved guidance paths, fresh fixture isolation, real Git-root boundaries without commits, malformed traces, unknown usage, command deduplication, incomplete tool attempts, missing responses, truthful execution coverage, content-based preservation checks, complete-chain comparison gates, durable anonymous allocations, strict dimension/criterion grading, frozen guidance inventories, path redaction, subject-versus-judge repetition identity, and reference-viewer export. Both unittest discovery and direct invocation run the complete suite.

An independent read-only reviewer identified comparison-integrity defects before final grading: incomplete runs entering pairs, allocation replacement, incomplete freeze coverage, added guidance escaping hash checks, silently absent prior sources, duplicate or invented grading criteria, and repeated judgments being mistaken for independent repetitions. Regression tests and repairs address these findings. The reviewer subsequently verified the initial fixes; the later repetition and dimension repairs have their own regression tests.

A trace audit of the first exploratory pilot found that ordinary Git commands walked from fixtures into the parent repository. The runner now initializes an unborn disposable repository in every fixture, so discovery stops at that fixture. No commits were created. That exploratory pilot is preserved and excluded from clean-isolation claims. Corrected runs verify the fixture boundary through actual command output as well as the independent harness test.

Source skills were not tuned during assessment. Skill files have identical hashes across the calibration snapshots. The first four snapshots share corpus/rubric version 1. Version 2 changes only c08: after both subjects implemented early, its second-stage prompt explicitly limits the turn to documents, and a corresponding outcome checks the source stub remains unchanged until stage three. This is an evaluation-input correction, not a skill revision; original evidence is retained. Runner/reporting corrections are separately preserved in each run's source snapshot and the first pilot's explicit freeze addendum. The source snapshots record the old driver used by an already running process; later reporting fixes do not rewrite subject evidence.

The default host model selection was held the same across paired calls, but the CLI event stream did not disclose a resolved model identifier. CLI version, requested model (null for host default), exact commands, raw events, reported usage, durations and artifact states are retained. The host still exposes its normal system context and skill catalog. This is therefore a supplied-guidance comparison, not a perfectly isolated skill-loader benchmark. Case-level skill lists are forced in behavior runs, including fresh stages; measured overhead includes that forcing and concurrent inference load, and should not be read as deployed-product latency.

Markdown-only and routing subjects are instructed to make zero tool calls. The runner uses a read-only command sandbox and audits both started and completed tool events; it does not claim the host physically removed every tool. Repository review manifests and unavailable symlink/service constraints are fictional fixture evidence, not proof of native Copilot activation, operating-system denial, committed-revision inclusion, or live issue-tracker behavior.

The static review viewer is generated with the supplied Anthropic helper, using its documented `--static` interface and a compatible existing bundled Python runtime. No server, installation, or global configuration change is required. Its embedded run/artifact inventory is checked against the export. Human usefulness judgments and submitted viewer feedback remain pending.
